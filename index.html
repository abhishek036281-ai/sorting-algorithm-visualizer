How it works:

Bubble Sort Theory

Comparison-based swapping algorithm
Stable
Introduction & Working Principle

Bubble Sort repeatedly steps through the list, compares adjacent elements, and swaps them if they are in the wrong order. With each full pass, the largest remaining element bubbles up to its correct final position at the end of the array.

Best Case Ω(N)
Average Case θ(N²)
Worst Case O(N²)
Auxiliary Space O(1)
Advantages
  • Simple to understand and implement for beginners.
  • In-place algorithm requiring $O(1)$ auxiliary memory.
  • Stable sort: preserves relative order of equal keys.
  • Early exit optimization detects already-sorted data in $\Omega(N)$ time.
Disadvantages
  • Very inefficient on large datasets with $O(N^2)$ quadratic complexity.
  • Excessive element swaps compared to Selection Sort.
Real-World Applications

Useful in computer graphics and game engines when polygon vertices are nearly sorted frame-to-frame, or on low-power microcontrollers with tight ROM limits where code size matters more than raw speed.

Arrays in Memory

An array is a contiguous block of memory where each element occupies a fixed number of bytes. The address of index $i$ is calculated instantaneously via $Address(i) = Base + (i \times Size)$, granting $O(1)$ random access time.

The Cost of Comparisons

Comparison-based sorting algorithms decide ordering strictly by querying whether $A[i] \le A[j]$. Information theory dictates that any comparison sort requires $\Omega(N \log N)$ comparisons in the worst case to distinguish between the $N!$ possible array permutations.

What Happens in a Swap?

A swap exchanges two values in memory using a temporary register: temp = A; A = B; B = temp;. While in-place swaps need $O(1)$ extra space, excessive swapping (like Bubble Sort) degrades performance due to frequent memory cache writes.

Divide-and-Conquer Paradigm

Divide-and-conquer decomposes a problem into subproblems of identical structure, solves them recursively, and merges the solutions. Merge Sort achieves $O(N \log N)$ complexity because the recursion tree has a depth of $\log_2(N)$ with $O(N)$ work performed per level.

Comprehensive DSA Glossary

Essential technical terms and theoretical definitions

In-Place Algorithm

An algorithm that transforms input without using auxiliary data structures proportional to input size. Auxiliary memory is strictly $O(1)$ or $O(\log N)$ for call stack.

Stable Sorting

A sorting algorithm is stable if two objects with equal keys appear in the sorted output in the exact same relative order as in the input array.

Auxiliary Space

The extra temporary memory allocated by the algorithm outside the memory holding the input data itself. For example, Merge Sort requires $O(N)$ auxiliary buffer space.

Big-O Notation (O)

Represents the asymptotic upper bound of algorithm runtime growth as input size $N \to \infty$. It describes the guaranteed worst-case execution envelope.

Big-Omega (Ω) & Theta (θ)

$\Omega(N)$ describes the asymptotic lower bound (best possible scenario). $\theta(N)$ denotes a tight bound where upper and lower bounds grow at identical rates.

Inversions in an Array

A pair $(A[i], A[j])$ is an inversion if $i < j$ and $A[i] > A[j]$. A sorted array has 0 inversions; a reversed array of size $N$ has $\frac{N(N-1)}{2}$ inversions.

Recursion Stack

Stack frames allocated in system memory for recursive function calls storing return addresses, parameters, and local variables. Merge Sort uses $O(\log N)$ stack frames.

Internal vs External Sorting

Internal sorting occurs entirely inside main RAM memory. External sorting processes massive datasets that do not fit in RAM using secondary storage disk partitions (e.g., External Merge Sort).
